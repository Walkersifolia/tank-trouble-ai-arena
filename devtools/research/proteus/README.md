# PROTEUS 评测与复盘

**最终 264 局已完成：Astra Gen4 · 无相显著优于 Gen3，但未达到“碾压 Opus”或“多人无弱点”的目标。** 对 Opus 单挑为 21 胜 18 负 1 平（52.5%）；四人赛赢 28/64，Opus 赢 30/64。以下只统计冻结后未参与调参的新种子，不使用开发阶段 65% 等成绩代替最终结果。

「无形可测，无隙可乘。」对应独立选手文件 [`bots/astra-g4-proteus.js`](../../../bots/astra-g4-proteus.js)。最终源码固定于 [`77f0b3cff3d7c2149e4b15b51a4322286e7061bc`](https://github.com/Walkersifolia/tank-trouble-ai-arena/commit/77f0b3cff3d7c2149e4b15b51a4322286e7061bc)，评测在北京时间 2026-11-07 07:13–07:54 执行。此后没有根据最终种子修改策略或重跑不利结果。

## 最终协议

- Node v24.18.1，同一 Node 进程只编译四份正式脚本一次，每局创建全新 VM 实例；串行调用同一个正式 `runMatch()`。
- 直接使用 Web 主版 `ArenaWorld`、公开 `observe()` 和正式 50 ms 单次决策预算；包含策略调用及动作字段读取，250 ms 无返回硬中断。物理始终 60 Hz，单局 60 秒，墙体不可破坏。原对手和物理未改。
- 单挑五配对：Gen4 分别对 Gen3、Opus、导师，以及 Gen3 对 Opus、导师。每个模式每配对 10 个新种子 × 两出生位，共 200 局；每个种子交错五配对，配对顺序随种子循环轮换，减少编译阶段与负载先后偏差。
- 四人模式同时加入 Gen4、Gen3、Opus、导师，每个模式 8 个新种子 × 四出生位轮换，共 64 局。
- 无道具单挑种子 `1100100–1100109`；有道具单挑 `1200100–1200109`；无道具四人 `1300100–1300107`；有道具四人 `1400100–1400107`。
- `trace off`；最终文件保留所有每局结果、选手统计、故障、拾取、死亡及护盾事件。省略逐发开火事件，仍保留发射次数和所有武器死因。五份最终 JSON 合计约 865 KiB，没有完整逐帧大录像。

这是可信本地脚本的 Node VM 评测，不是浏览器 iframe/Worker 的执行隔离实现。真实计时包含系统抢占，原版限时搜索也会随 JIT/负载选择不同动作，所以固定种子不保证逐 Tick 重现；所有选手遵守相同预算，超时仍判负并计入结果。本轮未修改 ORACLE 的源码、模型、数据或训练方案，也未对其执行停止或重启操作；没有为评测固定系统后台负载。导师是用户单独授权公开的原版 `bots/deepseek-g5-mentor.js`，未发布神谕目录。

## 行为、道具与已知失败

Gen4 共参加 184 局（120 单挑 + 64 四人），126 胜 57 负 1 平，183 次主动击杀、2 次自杀、0 次局时到、0 次决策超时或脚本故障。其最大已测决策为 26.108 ms；这只描述本机本批，不保证其他设备也相同。

| 选手 | 本批参赛局 | 请求强移动却低速度 tick | 占该选手决策 tick | 最长连续低速度 | 快速转向反转 | 每千决策 tick 反转 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Gen4 | 184 | 396 | 0.36% | 28 tick / 0.467 s | 10356 | 94.4 |
| Gen3 | 184 | 1375 | 1.65% | 70 tick / 1.167 s | 5070 | 60.8 |
| Opus | 144 | 1000 | 1.09% | 30 tick / 0.500 s | 9971 | 108.9 |
| 导师 | 144 | 1326 | 1.95% | 127 tick / 2.117 s | 4170 | 61.4 |

低速度定义为存活且 `|move| >= 0.5`、实际平移速度低于 12 px/s；快速反转是有效转向符号变化间隔不超过 12 tick。它们是行为代理，低速度不等于卡墙，快速指令反转不等于可见抽搐。Gen4 没有记录到超过 0.467 秒的连续强移动低速度片段，但不能据此宣称不存在接触或视觉问题。各选手对手组合和存活时长不同，上表不作统一强度排名。

Gen4 实际拾取 16 次：地雷 4、激光 2、护盾 7、散射 3。其有道具四人赛只拾取了 5 次护盾，不能据此声称已充分验证多人激光/散射争夺。最终死亡事件保留了激光、散射、地雷等真实武器死因；Gen4 本批死亡来自普通弹 57 次、散射 1 次。

需要保留的明确失败证据：

- 有道具单挑 `1200104 / rotation 0` 对 Opus：Gen4 在 tick 514 被自己两次反弹后的普通弹击杀。
- 有道具单挑 `1200106 / rotation 1` 对导师：Gen4 在 tick 188 被自己一次反弹后的普通弹击杀；该局最长连续低速度 22 tick。不能宣称自弹安全已经彻底解决。
- 开发阶段的既有 `6102` 构造对照中，最终底座 integrated3 的激光第三方局仍在 tick 48 阵亡，夹击局 tick 611 阵亡；它们不计入上述 264 局。见 [构造失败记录](development-scenarios-integrated3-multifront.json)。multifront 虽赢一个夹击构造局，却在自然三人对照中 1 胜 2 负，未替换 integrated3。
- 真实四人结果为 Gen4 28 胜、Opus 30 胜，证明“多人可靠且无明显弱点”仍未达到。保留当前最佳版本与证据，不继续用最终种子调参。

Opus 来源为 [PR #2](https://github.com/Walkersifolia/tank-trouble-ai-arena/pull/2)，原提交 `85305b7da0f540810f6926e5a7fbfbd1eda209e1`。Gen4 保留来源与 MIT 信息，复用已公开价值网络进行推理，没有训练神经网络。正式改动包括公开观测下的提前开火预测、连续追瞄、可执行的车体/炮管转角路径及多激光威胁容量；没有改变引擎或对手输入。

`run.mjs` 的 `duel` 模式让第一名分别对后续选手；`roundrobin` 两两对战；`ffa` 全员自由混战。策略只收到公开观测，不读取对手实例的私有状态；工具不调用 ORACLE，仅用于可信本地脚本。普通研究命令例如：

```powershell
node devtools/matches/run.mjs --bot astra-g4-proteus=bots/astra-g4-proteus.js --bot astra-g3-imperator=bots/astra-g3-imperator.js --bot opus-g1-prescience=bots/opus-g1-prescience.js --mentor bots/deepseek-g5-mentor.js --mode duel --seed 6100 --seeds 2 --powerups on --trace off --out local-data/results.json
```

`scenarios.mjs` 复用正式地图与物理，仅摆放初始位置、第三方冷却与激光持有状态，用于侧介入、两侧夹击和激光介入诊断。它是构造局，不混入自然胜率：

```powershell
node devtools/research/proteus/scenarios.mjs --mentor bots/deepseek-g5-mentor.js --candidate bots/astra-g4-proteus.js --out local-data/scenarios.json
```

开发种子为 `6100–6102`、`920100–920109`、`930100–930104`。早期 v3 的 100 局完整报告及 9 局中断摘要已明确列为 `development-v3-*.json`；其他 `development-*.json` 同样只表示对应候选的开发证据。最终文件只包含新种子 264 局，不能与反复开发样本合并推算胜率。
