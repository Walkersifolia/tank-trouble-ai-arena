# 开发指南：从可运行脚本到自己的策略

当前比赛允许反复迭代。本指南帮助定位算法该改哪里；字段、物理与结算细节以 `API.md` 为准。

## 1. 认识现成模板

`bot.js` 是简单追踪选手，按职责拆开，便于替换策略：

| 位置 | 当前行为 | 可以改造的方向 |
| --- | --- | --- |
| `SETTINGS` | 距离、角度、射击间隔等战术参数 | 根据公开对局反馈调整 |
| `memory` | 目标 ID、射击时间、遇阻计时 | 有限历史轨迹、目标切换、战术状态 |
| `chooseTarget` | 保持活目标，否则选最近目标 | 可达性、风险、对手武器与攻击机会 |
| `shortestAngle` | 计算最短转向角差 | 各策略共用正确的角度约定 |
| `planMovement` | 朝目标移动，遇阻短暂倒车 | 格子寻路、拐角余量、躲避来弹 |
| `chooseFire` | 对准且到达自己的节奏时尝试开火 | 目标提前量、自伤风险、武器类型 |
| `update` | 合并同 Tick 动作 | 协调移动、转向、开火和布雷 |

它没有寻路、躲弹、跳弹预测或道具争抢，不代表推荐比赛强度。先选一个具体行为改善，不必一次塞入所有算法。

## 2. 理解控制轴

左上角为原点，x 向右、y 向下；0 弧度朝右，正转向为顺时针。没有“向左走”的世界坐标动作，只有沿车头前进或后退。

```javascript
// 原地右转，仍可同时开火。
{ move: 0, turn: 1, fire: true, special: false }
// 倒车时仍可控制转向，不会自动把炮口翻转 180°。
{ move: -0.7, turn: -0.3, fire: false, special: false }
```

这两段是动作对象示意；完整可导入脚本见 `examples/pivot.js` 和 `examples/patrol.js`。

引擎先转向再移动。自己的短期运动预测也要使用这个顺序与 `state.dt`；预测不能直接修改坦克位置。原地不动仍可能被另一辆坦克的接触推开。

## 3. 决策资料

- `self`：自己的位置、朝向、实际速度、冷却、弹量、武器与护盾。
- `enemies`：其他所有选手，先按 `alive` 过滤。多人混战不固定敌人数。
- `map.cells`：格子连通关系，可用于 BFS/A*；`map.walls`：当前墙线段，可用于视线与反弹推算。格子连通不等于车体能贴角穿过。
- `bullets`：包含自己的弹。用 `id` 跟踪，不能默认 `ownerId===self.id` 就无害。
- `powerups`：当前地面道具；`mines`：仍可见的雷。雷可以隐去，只能自己记忆历史中见过的位置。
- `physics`、`rules`：公开常量和规则开关。不要把地图尺寸、武器参数和人数写死。

输入对象每 Tick 重新复制，只保留必要数据。每局作用域重置，不需要模拟跨局持久化。

## 4. 常见策略误区

**追人却一直顶墙：** 检查路线是否可达、是否经过格子中心、拐角是否考虑车体半径。模板的倒车脱困不代替寻路。

**躲弹时反而迎着弹走：** 坦克只能沿车头前后移动，目标方向与车身朝向不同。把候选 move/turn 转为短期轨迹后再比较来弹风险。

**一开火就自毁：** 靠墙的炮口可能被压回墙前；弹一反弹就可能伤到自己。不只要判断初始射线能否碰到敌人，还要考虑自己接下来的轨迹。

**总是转错方向：** 角差用 `atan2(sin(delta), cos(delta))` 归一化，读清正负方向。移动目标预测与角度变化是不同量，不能直接相加。

**每 Tick 都切换战术：** 可以用局内记忆设置短暂战术持续时间，采用 `state.time` 表达；切换条件应服务于战术，不盲目增加状态。

**突然超时：** 对可变人数、地图大小和弹数分配有限计算量。错误信息区分决策预算超时、执行后无响应和排队超时；设备排队不代表已经测得 update 超过 50ms。

## 5. 根据对战反馈迭代

按“观察问题 → 解释原因 → 修改相关策略 → 重新导入对战”推进。当前允许多次提交和真实对战，不保留旧提示词的一次提交限制。

向编程 AI 反馈时提供下面的信息即可，不需要给它其他选手源码：

```text
我的脚本：当前 bot.js
对局：真人挑战 / AI 混战，对手名称与参赛人数
规则：地图类型、时间限制、道具开关、破墙开关
观察：在什么情况下出现了什么动作，预期是什么
结果：获胜/失败/平局；若有报错，粘贴原文
希望改进：本次处理的具体行为
```

没有实际对局证据时，将推断标为推断。一次获胜或接口检查不能证明普遍胜率；由你决定需要运行哪些对局，不默认新增批量测试。

## 6. 本地单次输入检查的边界

`node check.js my-bot.js` 使用示例状态执行一次；`node check.js my-bot.js my-state.json` 使用指定状态。JSON 不会随动作改变，也不是一局比赛。工具不读取引擎、不预测结果，不生成性能评分。

检查器的 Node VM 不是完整浏览器运行环境，也不是用来执行恶意文件的安全沙箱。最终参赛环境是隔离 Worker；只提交单文件算法，并遵守 `API.md` 的能力限制。
