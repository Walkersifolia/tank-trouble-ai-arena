# Tank Trouble AI 开发工具包

工具包版本 **1.2.0** · 游戏接口 **API v1**

用一个 JavaScript 文件控制坦克，参加网页或 Electron 竞技场的真人挑战与 AI 混战。本目录可独立使用，不包含游戏引擎、高级选手源码、训练数据或比赛记录。

玩法可选“有道具对战”和“纯走位开火 · 无道具”，均关闭墙体破坏。读取 `state.rules.powerups` 选择策略；两种玩法保持同一 API 和运动参数，不要求训练模型才能参赛。

**当前规则允许迭代：可以实际对战、根据反馈修改脚本、重新导入并继续挑战，不限制一次提交。**

## 五分钟开始

1. 解压 ZIP，把 `AI_Starter_Kit` 放到独立工作目录。
2. 想让编程 AI 开发：把整个目录交给它，并复制 `prompt.md` 的内容作为任务提示词。不要只发提示词而遗漏 `API.md`。
3. 自己开发：先读 `API.md`，从 `bot.js` 开始修改。它是可读的追踪示例，不是高级参赛算法。
4. 打开网页，点击“导入 JS”，选择最终 `.js` 文件；在“本局阵容”设置自定义名称、颜色与控制者。
5. 选择真人挑战或 AI 观战，可同时加入多个网站选手和自定义脚本。修改后重新导入，取消勾选或移除旧席位，即可继续对战。

浏览器游戏不要求安装 Node.js。只有使用本包的可选命令行检查器时，才需要 **Node.js 20+**；工具包自身无需 `npm install`，没有第三方依赖。

## 包内文件

| 文件 | 用途 |
| --- | --- |
| `prompt.md` | 可直接交给编程 AI 的中文开发提示词，明确允许迭代 |
| `API.md` | 输入字段、动作语义、物理、武器、时序及预算的权威说明 |
| `DEVELOPMENT.md` | 开发顺序、策略改造位置、常见误区与对战反馈方法 |
| `bot.js` | 可改造模板：选目标、瞄准、追踪、射击、简单遇阻倒车 |
| `examples/pivot.js` | 原地转向与间歇开火，演示独立控制轴 |
| `examples/patrol.js` | 前进、原地转向、倒车、倒车转向的分阶段控制 |
| `example_state.json` | 一份完整公开观测，不是完整比赛记录 |
| `check.js` | 对一个状态调用一次脚本，报告入口、动作格式或执行错误 |
| `package.json` | CommonJS 声明及可选 `npm run check` 命令 |

## 提交接口

```javascript
let ticksSeen = 0; // 局内记忆，每局重新初始化
module.exports = {
  update(state) {
    ticksSeen++;
    return { move: 0, turn: 0.3, fire: ticksSeen % 90 === 0, special: false };
  },
};
```

- 交付一个自包含、UTF-8 编码的 `.js` 文件；名称与颜色在网页设置，不由脚本返回。
- `move` 为 `[-1,1]`：正数前进，负数倒车；`turn` 为 `[-1,1]`：正数右转，负数左转。
- `fire`、`special` 为布尔值。四个动作可以同时输出，`special` 当前用于布雷。
- 炮口随车身旋转，没有独立炮塔或八方向平移。
- `update` 必须同步返回对象，不能返回 Promise、null、数组或非法动作。
- CommonJS 只是一种导出格式：运行时没有 Node.js 的 `require`、`process`、`fs`，也不能 import 其他文件。

## 可选命令行检查

在解压后的 `AI_Starter_Kit` 目录运行：

```sh
node check.js bot.js
node check.js examples/pivot.js
node check.js my-bot.js my-state.json
node check.js --help
```

也可用 `npm run check -- my-bot.js`。不指定状态文件时使用 `example_state.json`；自定义状态文件应符合 `API.md` 的结构。成功时打印动作，失败时退出码为 1。

**检查器每次只调用一次，不推进世界、不生成地图、不评价胜率，也不证明脚本在浏览器、移动设备或完整比赛中一定通过 50ms 预算。** 它在新的 Node Worker 与 VM 中处理本次调用。检查器不是恶意代码安全沙箱，只对自己开发的脚本使用。

本包不会自动执行批量测试、创建回归框架或运行后台任务。需要运行检查时，按你的具体开发需求选择命令。

## 迭代方法

每次先改善一个具体问题，例如“贴墙自伤”或“倒车时瞄准失效”。重新导入后实际对战，把对手、地图类型、道具/破墙开关、参赛人数、报错原文及观察到的行为交给编程 AI。旧席位不会因磁盘文件改变而自动更新，必须重新导入。

玩家导入的源码只留在当前页面内存，不上传网站，不写入网页战绩；刷新后需重新导入。网页战绩与 Electron 正式排行榜独立。开发时可使用允许的公开对战反馈，但不能读取其他选手算法、游戏私有实现、未来状态或越权控制游戏。

## 必须理解的运行规则

- 物理固定 60Hz，`dt=1/60`；全部有效决策到齐才推进 Tick。手机性能不足时模拟变慢，规则与弹速不变。
- 每个存活选手每 Tick 获得同一时间点的独立公开状态副本。`enemies` 包含死亡者，选目标时读取 `alive`。
- 单局模块变量、闭包与对象状态可以保留；每局创建新执行实例，没有跨局记忆或局末回调。
- 正式单次决策预算 **50ms**，包含动作字段读取。另有执行开始后 **250ms** 无响应终止，以及初始化/排队各 **2000ms** 上限。预算与调度延迟的区别见 `API.md`。
- 异常、非法动作或超时只使该选手本局判负，其余选手继续。浏览器线程调度及 OS 抢占可能影响实测决策耗时。
- 脚本在隔离 iframe 创建的独立 Worker 中运行，禁止 DOM、Cookie、LocalStorage、网络、文件系统、计时器、子 Worker 和外部大模型 API。各选手不能访问彼此的脚本状态。
- 32MiB 是建议状态用量，不是强制内存配额；浏览器没有每个选手的独立内存硬上限。

## 常见问题

| 现象 | 先看哪里 |
| --- | --- |
| “必须导出 update” | 使用 `module.exports = { update(state) { ... } }`，不要用 ESM export |
| 动作格式错误 | 数值必须有限且在 `[-1,1]`，开火/特殊是布尔值 |
| 原地打转或不会倒车 | 区分世界方向与履带轴，检查最短角差和 move/turn 符号 |
| 反弹后自己死亡 | 自己的弹也有危险；反弹会立即取消未反弹弹的短暂自伤豁免 |
| 选手超时判负 | 查看具体错误码；排队延迟不等同实测决策超过 50ms |
| 修改后对局没变化 | 重新导入修改后的 JS，停用旧席位，再开始新一局 |

完整规则以 `API.md` 为准；本包没有提供完整游戏模拟器或自动调参平台。
