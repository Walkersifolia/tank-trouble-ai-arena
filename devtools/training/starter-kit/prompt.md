## 交付与接口

默认将最终脚本写为 `bot.js`；我指定其他文件名时，使用该名字。

```javascript
module.exports = {
  update(state) {
    return { move: 0, turn: 0, fire: false, special: false };
  },
};
```

- 单文件、自包含、同步 CommonJS。不要使用 import、require、第三方依赖、异步函数、Promise 或额外入口回调。
- `move`、`turn` 是 `[-1,1]` 内的有限数；`fire`、`special` 是布尔值。不要输出 NaN/Infinity 或超范围动作。
- 四项控制可同时进行：前进/倒车、原地转向、移动中转向射击都合法。炮口随车身，没有独立炮塔或八方向平移。
- `move>0` 前进、`move<0` 倒车；`turn>0` 顺时针右转、`turn<0` 逆时针左转；`special` 用于布雷。
- 每局使用新作用域；局内可以保存顶层变量、对象、数组等记忆。记住实体 ID，而不是某 Tick 对象引用。
- 脚本不能访问主页面、存储、文件、网络、操作系统、计时器、其他 Worker 或其他选手；游戏运行时不得调用任何外部大模型 API。

## 正确理解规则后再设计策略

1. 固定物理 60Hz，`dt=1/60`，使用 `state.time`/`tick` 表达战术时机，不把画面帧率或真实墙钟当成模拟时间。
2. 单次正式决策预算统一为 50ms；把常规决策控制在数毫秒更有利于手机流畅运行。不要通过死循环、异步任务、超时或消息协议规避比赛。
3. 读取当前 `map` 尺寸、`physics` 常量及 `rules`，不写死两人局地图，也不假定对手数量。`enemies` 中可能有已死亡选手。
4. 输入是公开状态副本。修改它不会改变游戏；不能获得未来状态、敌方算法或隐藏地雷的位置。
5. 每 Tick 按起始朝向设置线速度，同时推进转向，再处理射击；前进与倒车速度不同，按公开参数预测车身和炮管接触。坐标 y 向下，角度单位为弧度，正方向顺时针。
6. 普通弹会镜面反弹且可能自伤；散射、激光、地雷、护盾按 `API.md` 处理，不能都当作普通炮弹。
7. 当前墙体不可破坏。有道具模式保留全部道具，纯走位开火模式只用普通炮弹；读取 rules.powerups，不要假定一定有道具。隐形地雷消失于观测不等于已爆炸。

## 策略目标

在预算内协调生存、瞄准、移动和开火，提升对战表现。可按需要设计寻路、弹道预测、目标运动估计、轨迹采样或战术状态机，不要为了使用某种术语而堆砌算法。

优先考虑可达路线与车身/炮管轮廓、贴墙/自身回弹风险、多个目标与多颗弹体、倒车保持朝向、武器冷却与弹体上限、攻击机会和道具收益。不同模块应共享一致的动作计划，避免一个要求逃跑而另一个盲目开火。

在现有示例基础上直接实现。不要复制示例后仅改名就宣称完成高级 AI，也不要承诺没有实测依据的胜率。
