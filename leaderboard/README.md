# 官方 AI 战力榜与个人战绩

[打开官方战力榜](https://walkersifolia.github.io/tank-trouble-ai-arena/leaderboard/)。页面直接读取本目录 `data/` 的公开聚合结果，所有访客看到同一份官方数据。维护者在电脑上串行评测，再提交导出结果到 Pages；没有账号、数据库、成绩上传或常驻服务。

`local.js` 继续统计本浏览器娱乐对局，保留原来的 `tank-trouble-web-challenge-v1` localStorage 键、`aiStats` 字段和排序行为。官方工具不读取或写入个人战绩。真人挑战、训练场、公开 AI 策略与游戏规则均沿用原实现。

## 积分

- 单挑：胜／平／负得 100／50／0 分。先计算对每位对手的每局平均得分，再对所有对手等权平均。
- 四人混战：每局赢家 100 分，其余 0 分。无人获胜也为 0 分，并单列无人获胜局数；分项成绩是平均每局得分。
- 综合分 = 单挑分 × 50% + 混战分 × 50%，满分 100。同分并列，使用未舍入的成绩确定名次；击杀、自杀、局时到、决策超时和故障只作辅助统计。
- 沿用正式运行器每名选手的 `outcome`，故障记负、0 分，仍计入场次与分母。不能由空 `winnerId` 推断所有人都平局；全员故障另行统计。
- 统一赛程全部完成后才发布正式分数与名次。此前所有选手显示“评测中”；已产生的分项分数仅为暂定统计。尚未参加某类比赛时显示空缺，不以 0 分替代。

## 固定赛季与赛程

名单只从 `bots/roster.json` 读取，包括基础 AI 与历史代际，不扫描任何私有目录，不含神谕。正式赛季必须使用全部公开选手。

默认有道具、墙体不可破坏、每局 60 秒、物理 60 Hz、单次决策 50 ms、硬中断 250 ms、初始化 2000 ms。工具直接调用 `devtools/matches/run.mjs` 导出的 `loadEntrant()` 和 `runMatch()`；物理、公开观测、初始化与故障结算均使用原引擎及运行器。每局重新创建策略 VM，比赛串行运行，不并行争抢决策预算。真实计时可能包含操作系统抢占，固定种子不保证逐 Tick 完全复现。

默认每对不同 AI 使用 50 个地图种子，每种子交换出生位，共 100 局。纳入 Opus Gen2「衔尾」后的 17 人为 136 对、13,600 局单挑。衔尾与其他选手全部使用本季实际比赛，不采用 PR 作者自报成绩。

四人赛使用四个不同选手。17 人默认 850 局，每人 200 局、每个出生位 50 局；与其他 16 人的平均同场次数是 200 × 3 ÷ 16 = 37.5，不能让每对都取同一个整数。赛程用循环移位保持每人场数和出生位完全相等，逐轮枚举四人基础分组并均衡各对的同场次数；实际最小／最大同场次数公开在赛程说明和每位选手的对阵计划中。两种模式交错运行，合计 14,450 局，不因新增选手而减少原定的每对／每人场数。

人数及场数可变：四人赛将每人场数向上取到 4 的倍数，以保持每个出生位等量。16 人时使用四阶有限域仿射直线设计：20 个四人组各轮换四座位，一个周期每人 20 局；200 局／人时可做到每对同场 40 次。其余人数及不足周期部分使用循环移位四人组。公开结果记录请求场数、实际场数、出生位次数、每对同场次数范围及调整说明，不承诺任意配置都能做到每对完全相等。至少需要四名公开选手。

创建时把名单、选手脚本的 Git 提交、引擎与运行器版本、完整编号／种子／出生位安排、评分工具版本和机器环境固定在本地 `season.json`。正式续跑要求相关源码与该 Git 版本相同，且 Node、V8、操作系统及 CPU 环境相同；其他无关提交和公开数据更新不影响续跑。策略、引擎或规则实质变化后创建新赛季，不混入旧季。新增公开选手从下一完整赛季参赛。旧季数据文件保留原版本和规则，不会被新季覆盖；旧研究结果不导入本榜单。

## 评测、暂停、续跑

在唯一工作区 `D:\Documents\ChatGPT\坦克动荡AI斗蛐蛐\tank-trouble` 执行，使用 Node.js 20+。

```powershell
# 创建固定赛季；不运行比赛。正式工具与参赛源码应先提交到 Git。
npm run leaderboard -- init --season 2026-s1 --label "2026 · 第一赛季"

# 开始或续跑：只补未完成比赛，不改变原计划。
npm run leaderboard -- run --season 2026-s1

# 在另一个终端请求暂停；当前局结束并保存后停止。
npm run leaderboard -- pause --season 2026-s1

# 查看完成／计划局数、两类进度、暂定统计和实际用时估算。
npm run leaderboard -- status --season 2026-s1

# 同一个 run 命令续跑，清除已处理的暂停请求。
npm run leaderboard -- run --season 2026-s1

# 也可完成本次 N 局后正常暂停，计划总局数不变。
npm run leaderboard -- run --season 2026-s1 --limit 10
```

前台运行时按一次 Ctrl+C 同样请求局后暂停。强制终止或断电时，尚未完整写入结果行的比赛不计分，续跑会重做该局；已经完成的比赛按编号跳过。不要同时启动两个评测进程，避免改变真实计时负载。运行时不修改参赛代码，也不调整对手或预算。

`local-data/leaderboard/<赛季>/` 保存 `season.json`（固定赛程和版本）、`matches.jsonl`（完成一局追加一行）、`run.json`（运行状态）及暂停请求。逐局记录包括比赛编号、选手顺序、种子、出生位置、胜者、每位选手 outcome、统计和故障；选手版本关联固定名单，足以核算成绩。不存逐帧录像，不创建整项目副本。该目录沿用现有忽略规则，不提交。

## 导出与发布更新

```powershell
npm run leaderboard -- export --season 2026-s1

# 核对提交只包含公开页面、工具、说明和聚合数据后，正常提交／推送 main。
git add leaderboard/data/2026-s1.json leaderboard/data/seasons.json
git commit -m "Update official league progress"
git push origin main
```

`run` 正常暂停或完成时也会自动导出官方赛季。导出命令可以在另一终端读取运行中的已完成记录。`data/seasons.json` 是历史索引，`data/<赛季>.json` 是轻量聚合成绩，包括对阵与辅助统计；不会上传本地逐局日志。Pages 沿用 **main / 根目录**，无需构建网页、复制到 dist 或运行额外服务。只有推送后访客才看到此次更新；页面的更新时间是已发布数据的导出时间，运行状态也表示该次导出时的状态。

```powershell
npm run leaderboard -- run --season trial-20261107
# 在另一终端 pause，随后用相同 run 命令续跑。
```

此配置有 12 局单挑和 4 局四人混战。试跑状态与结果仅留在本地，`export` 不接受 trial 赛季；不能把试跑成绩或 `devtools/research/proteus/` 的历史结果拼进官方成绩。正式全量赛程不会因试跑耗时而减场或放宽预算。

2026-11-07 的该次真实试跑已完成 16／16 局：在第 2 局混战进行中请求暂停，完成并保存第 2 局后停止，续跑从第 3 局接上，最终为 12 局单挑、4 局混战。按逐选手结果汇总的单挑分分别为哨兵 0、无相 50、导师 66.6667、先机 83.3333；混战无相获胜 3 局、先机 1 局，分项为 75 与 25，其他为 0。均为试跑成绩，不进入官方榜。纯对战累计 160.606 秒，单挑平均 6.185 秒、混战平均 21.597 秒；按两模式均值外推 17 人正式计划约 28.5 小时。该小样本只含上述四名选手，不含衔尾；正式实际速度以本季记录和进度估算为准。
